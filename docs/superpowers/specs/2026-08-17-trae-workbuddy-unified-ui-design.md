# TRAE 与 WorkBuddy 统一界面及云端签到整合设计

## 目标

在不改变现有账号数据和签到协议的前提下，统一 TRAE 与 WorkBuddy 的账号管理界面，并把 WorkBuddy 的远端签到能力整合到“云端签到”页面。用户应能一眼识别账号所属产品，同时在一个页面查看和操作两类云端签到账号。

## 已确认方案

云端签到采用“同一账号列表 + 产品标签 + 顶部筛选”的方案。顶部提供“全部、TRAE、WorkBuddy”三个筛选项；默认显示全部账号，每张卡片必须展示产品图标和产品名称。

未采用的方案：

- 分成 TRAE 与 WorkBuddy 两个独立标签页：区分最强，但跨产品查看需要来回切换。
- 上下两个固定分区：实现直接，但账号较多时页面过长，且难以只关注某一产品。

## 导航与命名

- 侧栏原“账号切换”改名为“TRAE”。
- “TRAE”导航项使用现有 `src/assets/icons/trae-cn.png`，不再使用通用切换箭头。
- “WorkBuddy”继续使用 `src/assets/icons/workbuddy.png`。
- “云端签到”保持现有名称和云端图标。
- 应用品牌区仍显示“切换工具”，本次不调整产品名称或窗口标题。

## 账号管理页面

TRAE 与 WorkBuddy 页面继续保持独立业务组件和状态仓库，但共享同一套视觉结构：

- 相同的页面边距、标题字号、标题图标尺寸和标题栏高度。
- 相同的安装检测横幅、反馈横幅、账号网格列宽、卡片圆角和按钮层级。
- 相同的空状态结构和加载反馈。
- 主操作统一使用主题色按钮，查询、同步、设置等次要操作使用普通按钮，删除操作只在确认阶段使用危险色。
- 当前账号使用相同的边框高亮和“使用中”标记。

业务字段不强行拉平：TRAE 仍显示快照完整度、积分和 GitHub 槽位状态；WorkBuddy 仍显示手机号、UID、令牌有效期、积分、今日奖励和连续签到。统一的是结构和交互层级，不是删减各产品特有信息。

## 云端签到页面

### 筛选与区分

页面标题下方增加分段筛选控件：

- “全部”：显示 TRAE 与 WorkBuddy 的所有账号。
- “TRAE”：只显示 TRAE 账号。
- “WorkBuddy”：只显示 WorkBuddy 账号。

每张账号卡片显示产品图标、产品标签和账号名称。TRAE 与 WorkBuddy 使用各自图标，不依赖颜色作为唯一识别方式，以兼顾暗色主题和可访问性。

### TRAE 卡片

保留现有能力：

- Token 剩余时间与过期预警。
- 刷新凭证流程。
- 单账号同步 GitHub。
- 本地签到诊断。
- 当前使用账号标记。

### WorkBuddy 卡片

整合现有 WorkBuddy 状态仓库和远端命令，展示：

- Token 到期时间。
- 积分、今日奖励、连续签到。
- 是否参与自动签到。
- GitHub 同步状态。
- 状态查询错误和操作结果。

提供以下操作：

- “刷新状态”：只查询该账号积分及签到状态。
- “同步”：调用现有 WorkBuddy 聚合 Secret 同步；界面明确说明这是 WorkBuddy 远端账号集合，而不是 TRAE 槽位 Secret。
- “立即云端签到”：调用现有按账号筛选的 `trigger_workbuddy_checkin`，只触发目标 WorkBuddy 账号。

WorkBuddy 未启用“参与自动签到”时，立即云端签到按钮禁用，并提示先在 WorkBuddy 页面启用。

### 页面级操作和运行状态

- TRAE 的“立即验证签到”保留，但文案明确标为“验证 TRAE 签到”。
- WorkBuddy 使用卡片级“立即云端签到”，避免用户误以为页面顶部按钮会同时触发两个产品。
- 页面级同步拆成“同步 TRAE”和“同步 WorkBuddy”两个独立操作：前者同步 TRAE 槽位 Secrets，后者同步 WorkBuddy 聚合 Secret。按钮始终带产品名，不能用含义不清的“同步全部”代替。
- 现有 GitHub workflow 运行历史继续展示共享仓库的运行记录，并在可识别时根据 `displayTitle` 或触发上下文显示产品标签；无法可靠识别时显示“通用任务”，不能猜测产品。
- TRAE 最近运行横幅与 WorkBuddy 卡片操作反馈分开显示，避免将一类产品的成功状态套用到另一类产品。

## 状态与数据流

页面挂载时并行加载：

- TRAE 账号、GitHub 配置、GitHub CLI 状态和 workflow 运行历史。
- WorkBuddy 账号；仅在 WorkBuddy 账号可见或用户主动刷新时查询账号状态，避免进入页面时串行请求造成卡顿。

筛选仅影响渲染，不清空任一仓库中的账号和操作状态。TRAE 操作只锁定对应 TRAE 操作；WorkBuddy 操作沿用其按账号状态，并避免因一个账号查询而禁用所有无关账号操作。

WorkBuddy 的 GitHub 配置继续复用 TRAE 已有仓库和 workflow 文件配置。远端数据仍使用 `WORKBUDDY_ACCOUNTS_JSON` 聚合 Secret，TRAE 继续使用账号槽位 Secrets；前端只统一入口，不合并两种 Secret 格式。

## 错误与空状态

- TRAE 与 WorkBuddy 的错误分别标注产品来源。
- 某一产品加载失败时，另一产品账号仍可浏览和操作。
- 当前筛选没有账号时，空状态指出应前往哪个产品页面导入账号。
- GitHub CLI 或仓库配置未就绪时，远端按钮禁用并沿用现有设置引导。
- WorkBuddy 状态查询失败只影响对应账号卡片，不隐藏账号，也不阻断其他账号。

## 性能与响应性

- 不增加全局轮询。
- WorkBuddy 状态查询按账号独立执行，并允许独立显示加载状态。
- 避免在渲染期间重复触发 GitHub 或状态请求。
- 账号列表使用稳定账号 ID 作为 React key，筛选切换不重新创建业务状态。
- 保持现有响应式网格；窄窗口下分段筛选和操作按钮允许换行，文本不得溢出卡片。

## 测试与验收

### 自动测试

- 为签到产品筛选及产品识别辅助逻辑增加前端单元测试。
- 为 WorkBuddy 卡片的启用/禁用和状态文案增加可测试的纯函数覆盖。
- 保留并运行现有 TRAE、WorkBuddy Rust 测试，确认远端 Secret 和 `account_filter=workbuddy:<id>` 行为未回归。
- 运行 TypeScript 构建和 Tauri 正式构建。

### 手工验收

- 侧栏显示“TRAE”及 TRAE 图标，WorkBuddy 图标不变。
- TRAE 与 WorkBuddy 页面在标题、状态横幅、卡片和按钮层级上明显统一。
- 云端签到默认同时显示两类账号，并能通过三个筛选项正确过滤。
- 每张卡片无需阅读字段即可通过图标和文字判断产品。
- TRAE 的同步、本地签到和凭证刷新仍可用。
- WorkBuddy 能刷新状态、同步 GitHub，并按账号触发远端签到。
- 任一产品操作失败时，错误不会错误显示到另一产品。
- 宽屏与窄屏下无文字溢出、按钮重叠或明显布局跳动。

## 非目标

- 不修改 TRAE 或 WorkBuddy 的服务端签到协议。
- 不合并两类账号的数据模型或持久化文件。
- 不新建第二套 GitHub 仓库配置。
- 不调整客户端自动探测与账号切换后端逻辑。
- 不重新设计应用其他供应商页面。

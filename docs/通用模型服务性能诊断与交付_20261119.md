## 1. 复现到的缺陷与修复

| # | 缺陷 | 证据 | 修复 |
|---|---|---|---|
| 1 | `connection_keys_resolve_the_correct_pool` 依赖进程级环境变量，与其他并行测试竞争 | 全量 `cargo test --lib` 稳定失败：354 通过 / 3 失败 / 14 忽略，退出码 101；失败还毒化共享 env 锁，连带 2 个 `provider_current_state` 测试报 `PoisonError` | 抽出纯函数 `key_filename()`，测试改为直接校验三池文件名与独立读取，不再改环境变量 |
| 2 | 豆包池测试设置最高优先级 `QIEHUAN_YINGYONG_TEST_DATA_DIR` 却不持有 env 锁 | 二次实测 360 通过 / 2 失败，报错路径被重定向到 `doubao-web-test-<uuid>` 且目录已被删除（`os error 2`） | 测试体全程持有 `test_support::env_lock()`；`provider_current_state` 的 `DataDirGuard` 改用最高优先级变量，避免被低优先级别名覆盖 |
| 3 | 三池记录文本中英混用（`complete` / `stream relay ended` / `response send failed` 与中文并存） | 中文界面"调用记录"表直接显示英文结果 | `model_service` 统一 `RESULT_*` 常量，三池共用 |
| 4 | TRAE 入口 429 用**消息字符串相等**判定"入口过载拒绝" | 任何文案调整会静默降级为"请求失败"，统计失真 | 新增 `reply_classified()`，拒绝类型显式传参，不再比较文案 |

## 2. 新增回归测试

- 记录行字段白名单：只允许 `time/model/stream/status/result/relayMs`，断言不含 prompt、Authorization、Bearer、cookie 等。
- 12 线程 × 200 次并发写入后，每个池严格 50 条、无跨池串号。
- 入口过载 429 与账号占用 429 分类区分：`limited=2`、`entryRejected=1`。
- 平均转发耗时只统计"非流式 + HTTP 200"，流式与失败样本不进入均值。
- 调度器拒绝请求返回 `application/json` + `local_pool_error`，且该请求**从未进入** handler（防越权转发）。
- `live_single_call_latency`（默认 ignored，需 `QIEHUAN_LIVE_CONFIRM=1` 显式授权）。
